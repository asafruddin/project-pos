## Rules that are easy to get wrong

- **Expo changes every SDK.** This app is on SDK 57. Before touching an Expo/EAS/RN API, read the matching
  docs (`https://docs.expo.dev/versions/v57.0.0/`, index at `https://docs.expo.dev/llms.txt`). Do not trust memory.
- **Install with `npx expo install <pkg>`** (resolves SDK-compatible versions), run from `apps/mobile`.
- **Navigation is React Navigation** (`app/navigators/`), *not* Expo Router. Ignite-style `app/` folders, no Ignite starter deps.
- **Dependency direction:** `presentation → domain ← data / infrastructure`. `domain/` never imports React Native,
  `expo-*`, drizzle, or `fetch`. Wire adapters only in `app/core/di/container.ts`.
- **The UI never waits on the network.** Write to SQLite (+ outbox row, same transaction), then notify the scheduler.
- **Do not edit `android/` by hand** (generated by `expo prebuild`; gitignored). Native config goes in `app.config.ts` / config plugins.
- **DB changes:** edit `app/infrastructure/db/schema/`, run `pnpm --filter @pos-apps/mobile db:generate`, commit `drizzle/`.
- Not Expo Go: the app needs a development build (`expo run:android`).

## Commands (from repo root)

```bash
pnpm dev:mobile                                  # build shared packages + start Metro (dev client)
pnpm --filter @pos-apps/mobile android           # build + install the dev build on a device/emulator
pnpm --filter @pos-apps/mobile test              # jest (real SQLite via better-sqlite3)
pnpm --filter @pos-apps/mobile lint
pnpm --filter @pos-apps/mobile typecheck
```

Run lint, typecheck and tests before declaring work done.
